Embedding explorer — three linked views of 1,500 Push-T training latents

What this is. Three views of the same 1,500 latent vectors that LeWorldModel learned while predicting the next frame of Push-T: a UMAP scatter (2D layout of the latent manifold), a parallel-coordinates plot over the top PCA axes plus block pose, and an EVoC cluster treemap sized by cluster population. The views are linked: drag a brush or lasso on any one and the others highlight the same points, and a strip of thumbnails appears below showing exactly which frames are in the selection. The linked-selection idiom is borrowed from Vincent Warmerdam's evoc/Marimo demo. Honest note: EVoC clusters are unsupervised — we never told the model what a phase is, and the cluster structure is real but diffuse (silhouette ≈ 0.035 on this corpus; see world-model §7). Use this for browsing the latent space, not as semantic ground truth.

How this is built

The 1,500 points are uniformly subsampled from the training-time latents the LeWorldModel encoder produces on Push-T frames (192-d, per frame). For each point we store the top 8 PCA coordinates of that latent, a 2-D UMAP projection (n_neighbors=15, min_dist=0.1, cosine metric), the underlying Push-T state (block_x, block_y, theta, agent coords), and the cluster id from each of five layers of EVoC (Vincent Warmerdam's Evolutionary Vector Clustering), which we ran at depths producing 88, 28, 11, 5, and 2 clusters respectively. EVoC was chosen over k-means because it does not require k and exposes a hierarchy cheaply.

Thumbnails are pre-rendered Push-T frame crops packed into a single 39×39 sprite sheet (assets/explorer-data/sprite.jpg); each point indexes a tile, so the thumbstrip pulls 48×48 crops with one HTTP request total. The data file (explorer_data.json, ≈760 KB) and the sprite are committed under outputs/demo/explorer/ and symlinked into the site at assets/explorer-data/. All three views are rendered with vanilla D3 v7; no React, no build step. Source for each view is in assets/explorer/view_*.js; the shared selection store is in assets/explorer/state.js, and every view subscribes to it via LewmExplorer.subscribe(fn). The clusters here are not the same as the 8-cluster k-means treemap on the world-model page — that one is k-means at depth 1; this one is EVoC at five depths. Neither is supervised; treat both as structure that fell out of next-latent prediction, not as labeled phases.
