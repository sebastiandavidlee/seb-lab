Classification & Fundamentals

Logistic Regression — A linear model that outputs a probability via the sigmoid function: p = 1/(1+e^-z) where z = w·x + b. Despite the name it's a classifier, trained by minimizing cross-entropy (log-loss), not squared error. Related: sigmoid, cross-entropy, softmax, decision boundary
Softmax — Generalizes sigmoid to multiple classes: converts a vector of logits into a probability distribution, softmax(z)_i = e^{z_i} / Σ_j e^{z_j}. Sensitive to logit scale, which is why it's usually paired with a temperature term in calibration or distillation. Related: logistic regression, cross-entropy, temperature scaling, calibration
Cross-Entropy Loss — Measures the divergence between predicted class probabilities and the true one-hot label: -Σ y_i log(p_i). Convex in the logits for a single softmax layer, which is why it's the default classification objective over squared error. Related: softmax, negative log-likelihood, label smoothing, focal loss
Bias-Variance Tradeoff — Expected test error decomposes into bias² (error from a model too simple to capture the true function), variance (error from sensitivity to the specific training sample), and irreducible noise. Increasing model capacity typically lowers bias but raises variance; regularization and more data both primarily attack variance. Related: overfitting, regularization, capacity, ensembling
L1 Regularization (Lasso) — Adds λΣ|w_i| to the loss. Its non-differentiable corner at zero pushes many weights to exactly zero, producing sparse, more interpretable models — useful for implicit feature selection. Related: L2 regularization, sparsity, feature selection
L2 Regularization (Ridge / Weight Decay) — Adds λΣw_i² to the loss, shrinking all weights smoothly toward zero rather than sparsifying. Implemented in most optimizers as "weight decay"; the standard default regularizer for deep nets. Related: L1 regularization, AdamW, overfitting
Overfitting — A model fits the training set's noise/idiosyncrasies rather than the underlying signal, so training loss keeps dropping while validation loss rises. Symptom of low bias, high variance; fixed with regularization, more data, augmentation, or early stopping. Related: bias-variance tradeoff, dropout, early stopping, train/val/test split
Class Imbalance — When one class vastly outnumbers another (e.g. rare pedestrians vs. background in AV perception), naive accuracy is misleading and cross-entropy is dominated by the majority class. Fixed with resampling, class weighting, or a loss designed for imbalance like focal loss. Related: focal loss, PR-AUC, resampling, data leakage
Focal Loss — A cross-entropy variant, -(1-p_t)^γ log(p_t), that down-weights easy/well-classified examples so the model spends gradient budget on hard, misclassified ones. Standard in dense object detection where background examples vastly outnumber objects. Related: class imbalance, cross-entropy, object detection
Precision / Recall / F1 — Precision = TP/(TP+FP) — of predicted positives, how many were right. Recall = TP/(TP+FN) — of actual positives, how many were caught. F1 is their harmonic mean. In AV safety contexts recall on rare hazard classes usually matters more than precision. Related: PR-AUC, ROC-AUC, confusion matrix, class imbalance
ROC-AUC vs. PR-AUC — ROC-AUC plots true-positive rate vs. false-positive rate across thresholds; it's threshold-independent but can look deceptively good under heavy class imbalance because true negatives dominate. PR-AUC (precision vs. recall) ignores true negatives entirely, so it's the more honest metric when positives are rare — the common case in AV detection tasks. Related: precision/recall/F1, class imbalance, calibration
Calibration — A model is calibrated if its predicted confidence matches empirical accuracy — among predictions with 0.8 confidence, ~80% should be correct. Modern deep nets are often overconfident; fixed post-hoc with temperature scaling or during training with label smoothing. Related: temperature scaling, label smoothing, softmax
Label Smoothing — Replaces hard one-hot targets (e.g. [0,1,0]) with softened ones (e.g. [0.03,0.94,0.03]), discouraging the model from driving logits to extremes. Improves calibration and generalization at a small cost to peak training accuracy. Related: cross-entropy, calibration, overfitting
Data Leakage — Information from outside the training set (often indirectly, via preprocessing fit on the full dataset, near-duplicate frames across splits, or a feature that encodes the label) leaks into training, producing inflated validation metrics that don't hold at deployment. A classic AV example: consecutive video frames from the same clip landing in both train and val. Related: train/val/test split, distribution shift, overfitting
Train / Validation / Test Split — Train fits parameters; validation tunes hyperparameters and model selection; test gives a final, only-looked-at-once estimate of real-world performance. Splits must respect real-world grouping (e.g. by driving scenario or vehicle, not by frame) to avoid leakage. Related: data leakage, cross-validation, distribution shift
Decision Boundary — The surface in feature space where a classifier's predicted class changes. Linear models (logistic regression) produce a flat hyperplane boundary; deep nets can carve arbitrarily curved boundaries — more expressive but harder to reason about and more prone to overfitting the training set's noise. Related: logistic regression, overfitting, bias-variance tradeoff
Confusion Matrix — A table of predicted vs. actual class counts (TP, FP, TN, FN for binary) that all other classification metrics (precision, recall, F1) are derived from. The first thing to look at when a single accuracy number seems suspicious, since it exposes exactly which classes are being confused. Related: precision/recall/F1, class imbalance
Hyperparameter Tuning — Searching over settings the optimizer doesn't learn directly (learning rate, batch size, regularization strength, architecture width/depth) using the validation set, via grid search, random search, or Bayesian optimization. Must never touch the test set, or the "final" performance estimate becomes optimistic. Related: train/val/test split, learning-rate schedule
Cross-Validation — Splitting data into k folds, training on k-1 and validating on the held-out fold, rotating through all folds — gives a more robust performance estimate than a single train/val split when data is limited, at the cost of k× the training compute. Related: train/val/test split, hyperparameter tuning
Ensembling (Bagging / Boosting) — Combining multiple models' predictions to improve accuracy/robustness. Bagging (e.g. random forests) trains models independently on bootstrapped data samples and averages them, mainly reducing variance. Boosting (e.g. gradient boosting) trains models sequentially, each correcting the previous ones' errors, mainly reducing bias. Related: bias-variance tradeoff, dropout, knowledge distillation

Training & Scaling

SGD (Stochastic Gradient Descent) — Updates weights using the gradient of the loss computed on a small random mini-batch rather than the full dataset: w ← w - η∇L. The noise from mini-batching acts as an implicit regularizer and lets training scale to huge datasets. Related: learning rate, Adam/AdamW, batch size, momentum
Adam / AdamW — Adam adapts the per-parameter learning rate using running estimates of the first (mean) and second (variance) moments of the gradient, giving fast, robust convergence with little tuning. AdamW fixes a bug in vanilla Adam where L2 regularization interacted badly with the adaptive scaling — it decouples weight decay from the gradient update. AdamW is the default optimizer for most modern deep nets, including transformers. Related: SGD, weight decay, learning-rate schedule
Learning-Rate Schedule — How the learning rate changes over training — e.g. cosine decay, step decay, or linear decay to zero. Too high a rate causes divergence or oscillation; too low wastes compute and can get stuck in sharp minima. Schedules typically combine warmup with decay. Related: warmup, SGD, cosine annealing
Warmup — Linearly (or otherwise) ramping the learning rate up from ~0 over the first few hundred/thousand steps before applying the main schedule. Prevents early, poorly-conditioned gradients (especially in transformers with randomly initialized attention) from causing instability. Related: learning-rate schedule, transformer encoder/decoder
Batch Normalization — Normalizes activations to zero mean/unit variance across the batch dimension per layer, then applies a learned scale/shift. Stabilizes and accelerates CNN training but its statistics depend on batch size and composition, which causes issues at small batch sizes or during inference-time distribution shift. Related: layer normalization, internal covariate shift, CNN
Layer Normalization — Normalizes activations across the feature dimension per sample (not across the batch), making it batch-size-independent and well-suited to variable-length sequences. The standard normalization in transformers; batch norm is standard in CNNs. Related: batch normalization, transformer encoder/decoder
Dropout — Randomly zeroes a fraction of activations during training, forcing the network to not rely on any single unit and approximating an ensemble of subnetworks. Turned off at inference (or scaled to compensate). Related: overfitting, regularization, ensembling
Data Augmentation — Applying label-preserving transformations (crop, flip, color jitter, sensor-realistic noise, simulated rain/occlusion for AV) to training data to increase effective dataset size and robustness to nuisance variation. Related: overfitting, distribution shift, domain randomization
Curriculum Learning — Ordering training examples from easy to hard (rather than random shuffling) so the model builds up representations progressively. Used in AV pipelines to start on clean-weather/common scenarios before introducing rare, hard edge cases. Related: distribution shift, hard-example mining
Scaling Laws — Empirical power-law relationships (Kaplan et al., Chinchilla) between model size, dataset size, compute, and loss. The key practical takeaway: for a fixed compute budget there's an optimal balance of model size vs. data size — a big model is often "undertrained" if data doesn't scale with it. Related: data complexity, compute-optimal training
Distribution Shift — When the data seen at inference differs systematically from training data (new city, new weather, new sensor rig, night vs. day). The central risk in AV deployment; mitigated by domain adaptation/randomization, broader data collection, and continuous monitoring. Related: domain adaptation, domain randomization, data augmentation
Domain Adaptation / Domain Randomization — Domain adaptation explicitly aligns feature distributions between a source and target domain (e.g. sim-trained to real-world) via techniques like adversarial alignment or fine-tuning. Domain randomization instead trains on a wide, randomized range of simulated conditions so the real world just looks like "one more sample" — common in sim-to-real robotics/AV pipelines. Related: distribution shift, sim-to-real, data augmentation
Self-Supervised Learning (SSL) — Learning representations from unlabeled data using a pretext task derived from the data itself (predict masked tokens/patches, predict a transformation, match augmented views) rather than human labels. The dominant pretraining paradigm for both language and vision foundation models. Related: MAE, contrastive learning, pretraining, CLIP-style alignment
Contrastive Learning — A self-supervised objective that pulls representations of matching/positive pairs together and pushes non-matching/negative pairs apart in embedding space (e.g. SimCLR, CLIP). Requires careful negative sampling and large batch sizes to work well. Related: self-supervised learning, CLIP-style alignment, embedding space
MAE (Masked Autoencoder) — A self-supervised vision pretraining method: mask a large fraction (e.g. 75%) of image patches, encode only the visible ones, and train a lightweight decoder to reconstruct the masked pixels. Cheap to pretrain since the encoder never sees most of the image, and produces strong transferable features. Related: self-supervised learning, ViT, patch embedding
Knowledge Distillation — Training a smaller "student" model to match a larger "teacher" model's output distribution (often its softened, temperature-scaled logits) rather than only hard labels, transferring the teacher's learned generalization into a cheaper model. Related: temperature scaling, quantization, pruning, model compression
Momentum — Accumulates a running exponential average of past gradients and uses it (instead of the raw current gradient) for the update, damping oscillation across steep/narrow loss-surface directions and accelerating progress along consistent ones. Built into SGD-with-momentum and into Adam's first-moment estimate. Related: SGD, Adam/AdamW, learning-rate schedule
Vanishing / Exploding Gradients — In deep networks, repeated multiplication through many layers can shrink gradients toward zero (vanishing — early layers stop learning) or blow them up (exploding — training diverges). Addressed by residual connections, normalization layers, careful weight initialization, and gradient clipping. Related: ResNet, batch normalization, gradient clipping, weight initialization
Activation Functions (ReLU / GELU) — The nonlinearity applied after each linear layer, without which stacked layers would collapse into one linear map. ReLU (max(0,x)) is cheap and mitigates vanishing gradients but can "die" (permanently zero gradient) for negative inputs. GELU is a smooth, probabilistic variant standard in transformers (BERT, GPT, ViT). Related: vanishing/exploding gradients, ViT, transformer encoder/decoder
Weight Initialization — How weights are set before training starts (e.g. Xavier/Glorot, He initialization) — scaled so activation variance stays roughly constant across layers at the start, preventing immediate vanishing/exploding gradients. A bad init can make an otherwise-correct architecture fail to train at all. Related: vanishing/exploding gradients, batch normalization
Gradient Clipping — Rescaling gradients (by norm or value) when they exceed a threshold, before the optimizer step — a cheap safeguard against occasional large/exploding gradients, especially common early in transformer training or with long sequences. Related: vanishing/exploding gradients, warmup
Transfer Learning / Fine-Tuning — Reusing a model pretrained on a large, general dataset and adapting it to a target task, either by fine-tuning all weights on the smaller target dataset or by freezing the backbone and training only a new head (linear probing). Dramatically reduces the labeled data needed for the target task versus training from scratch. Related: self-supervised learning, catastrophic forgetting, LoRA
LoRA (Low-Rank Adaptation) — A parameter-efficient fine-tuning method that freezes the pretrained weights and injects small trainable low-rank matrices into each layer, updating only a tiny fraction of parameters. Makes fine-tuning large foundation models feasible on limited compute/memory, and multiple LoRA adapters can be swapped for different tasks. Related: transfer learning/fine-tuning, quantization
Catastrophic Forgetting — Fine-tuning a pretrained model on a new task/domain can overwrite the general knowledge learned during pretraining, degrading performance on the original distribution. Mitigated with lower learning rates, LoRA-style adapters that leave base weights frozen, or replay of original-domain data. Related: transfer learning/fine-tuning, LoRA, distribution shift
Multi-Task Learning — Training one shared backbone with multiple task-specific heads (e.g. detection + segmentation + depth from one AV perception encoder) jointly. Can improve data efficiency and generalization via shared representations, but requires careful loss-weighting across tasks so one task doesn't dominate the gradient signal. Related: multimodal encoder, sensor fusion (early/mid/late)

Inference & Deployment

Quantization (PTQ vs. QAT) — Reducing numeric precision of weights/activations (e.g. FP32 → INT8) to shrink memory and speed up inference. Post-training quantization (PTQ) quantizes a fully-trained model, often with a small calibration set — fast but can lose accuracy. Quantization-aware training (QAT) simulates quantization noise during training so the model adapts to it, typically preserving more accuracy at the cost of extra training. Related: AWQ, mixed precision, pruning, inference latency
AWQ (Activation-aware Weight Quantization) — A weight-only PTQ method that identifies the small fraction of weights most "salient" to activations (via activation magnitude statistics) and protects them from precision loss, while aggressively quantizing the rest — achieving near-lossless low-bit (e.g. 4-bit) compression without retraining. Related: quantization, model compression, inference latency
Pruning — Removing weights, channels, or whole structures that contribute little to output (by magnitude, gradient, or learned importance), producing a sparser and cheaper-to-run model. Unstructured pruning gives higher sparsity but needs specialized hardware/kernels to realize speedups; structured pruning (removing whole channels/heads) gives dense speedups on ordinary hardware. Related: quantization, knowledge distillation, model compression
ONNX / TensorRT-style Compilation — Exporting a trained model to a standardized computation-graph format (ONNX) and then compiling/optimizing it for a target runtime (e.g. TensorRT for NVIDIA GPUs) — fusing operators, selecting optimal kernels, and applying quantization — to minimize inference latency on the deployment hardware. Related: quantization, inference latency, mixed precision
Latency vs. Throughput — Latency is the time to process one request (critical for AV, a hard real-time constraint); throughput is total requests processed per unit time (matters for offline/batch training-data labeling). Techniques that improve throughput (large batching) often hurt latency, and vice versa — the two must be optimized for separately depending on the serving context. Related: batching, inference latency, real-time constraint
Batching — Grouping multiple inference requests to run through the model together, amortizing fixed overhead and improving GPU utilization/throughput. In latency-critical settings (AV perception) batch size is often forced to 1, so other techniques (quantization, compilation, hardware) carry more weight. Related: latency vs. throughput, inference latency
KV Cache — In autoregressive transformer inference, caching the key/value projections of previous tokens so each new token only computes attention against the cache instead of recomputing the whole sequence — the standard trick that makes generation cost roughly linear instead of quadratic in sequence length. Cache size grows with sequence length and batch size, often the binding memory constraint for serving. Related: attention Q/K/V, transformer encoder/decoder, inference latency
Mixed Precision — Using lower precision (FP16/BF16) for most computation while keeping select operations (e.g. loss scaling, some accumulations) in FP32 for numerical stability — speeds up both training and inference on hardware with native low-precision support, with minimal accuracy loss. Related: quantization, ONNX/TensorRT-style compilation

Architectures

CNN (Convolutional Neural Network) — Applies learned, spatially-shared filters (convolutions) over an image, giving built-in translation equivariance and a strong inductive bias for local, hierarchical visual structure. Pre-ViT default architecture for vision; still dominant where inductive bias and efficiency at small data matter. Related: ViT, FPN, receptive field, inductive bias
ResNet — Introduced residual/skip connections (y = F(x) + x) that let gradients flow directly through identity paths, solving the vanishing-gradient problem that previously made very deep CNNs hard to train. The skip-connection idea is now ubiquitous, including inside transformer blocks. Related: CNN, vanishing gradient, transformer encoder/decoder
ViT (Vision Transformer) — Applies the standard transformer encoder to images by splitting them into fixed-size patches, linearly embedding each as a token, and processing the resulting sequence with self-attention — trading the CNN's built-in spatial inductive bias for scalability, at the cost of needing more data/pretraining to match CNN performance from scratch. Related: patch embedding, attention Q/K/V, CNN, positional encoding
Patch Embedding — The ViT input step: cut an image into non-overlapping fixed-size patches (e.g. 16×16 pixels), flatten each, and linearly project it into a token embedding — the visual analog of tokenizing text into word/subword embeddings. Related: ViT, tokenization, positional encoding
Attention (Q/K/V) — The core transformer operation: each token produces a query, key, and value vector; attention weights are softmax(QK^T/√d), used to compute a weighted sum of values. Lets every token directly attend to every other token regardless of distance, unlike the local receptive field of convolution or the sequential bottleneck of RNNs. Related: cross-attention, transformer encoder/decoder, KV cache
Cross-Attention — Attention where queries come from one sequence/modality and keys/values come from another (e.g. text tokens attending to image patch tokens). The standard mechanism for fusing two modalities inside a transformer, as opposed to self-attention where Q/K/V all come from the same sequence. Related: attention Q/K/V, sensor fusion (early/mid/late), VLM
Transformer Encoder / Decoder — The encoder maps an input sequence to contextualized representations using self-attention (bidirectional — every token sees every other token); the decoder generates output autoregressively using causal self-attention (each token only sees earlier tokens) plus, in encoder-decoder models, cross-attention into the encoder output. Encoder-only (BERT-style) suits representation/classification tasks; decoder-only (GPT-style) suits generation. Related: attention Q/K/V, cross-attention, KV cache, warmup
Tokenization — Splitting raw input (text into subwords/BPE tokens, images into patches, point clouds into voxels/pillars) into the discrete units a model actually consumes. The choice of tokenization scheme fundamentally shapes what the model can represent efficiently. Related: patch embedding, voxelization, positional encoding
Positional Encoding — Since self-attention itself is permutation-invariant (order-blind), positional encodings (fixed sinusoidal, learned, or relative like RoPE) are added/injected to give the model information about token order or spatial location. Related: attention Q/K/V, patch embedding, transformer encoder/decoder
U-Net — An encoder-decoder CNN with skip connections directly linking each encoder resolution level to its matching decoder level, preserving fine spatial detail that would otherwise be lost through downsampling — the standard architecture for dense pixel-level prediction (segmentation, depth). Related: CNN, FPN, occupancy network
FPN (Feature Pyramid Network) — Builds a multi-scale feature pyramid by combining high-resolution/low-semantic features from early CNN layers with low-resolution/high-semantic features from deep layers via top-down pathways and lateral connections — lets a detector handle both small and large objects well. Standard backbone add-on for object detectors. Related: CNN, ResNet, object detection
RNN / LSTM — Recurrent networks process sequences step-by-step, carrying a hidden state forward; LSTMs add gating (input/forget/output gates) to control what information is kept or discarded, mitigating vanishing gradients over long sequences. Mostly superseded by transformers for sequence modeling, but still relevant for low-latency streaming/online settings where full-sequence attention is too costly. Related: transformer encoder/decoder, vanishing/exploding gradients, temporal fusion
Embedding — A learned, dense, lower-dimensional vector representation of a discrete or high-dimensional input (a word, an image, a point in a point cloud), positioned in a continuous space where geometric relationships (distance, direction) capture semantic relationships. Related: CLIP-style alignment, contrastive learning, cosine similarity
Cosine Similarity — Measures the angle between two vectors, (a·b)/(|a||b|), ignoring magnitude — the standard similarity metric for comparing embeddings (retrieval, contrastive learning) since embedding norm often carries little semantic meaning. Related: embedding, contrastive learning, CLIP-style alignment
Receptive Field — The region of the input image that influences a given output neuron/feature. Grows with network depth, kernel size, and dilation in CNNs; in ViTs, self-attention gives every layer a global receptive field from the start, which is one of its key advantages over convolution for capturing long-range context. Related: CNN, ViT, FPN
Anchor Boxes — Predefined reference boxes of various scales/aspect ratios tiled across the image that a detector regresses offsets from, rather than predicting box coordinates from scratch — simplifies the detection problem to classification + regression per anchor. Anchor-free detectors (e.g. predicting box centers/corners directly) remove this design complexity at some cost in recall for extreme aspect ratios. Related: object detection, IoU, NMS
IoU (Intersection over Union) — Measures overlap between a predicted and ground-truth box (or mask) as intersection area divided by union area. Used both as a training target (regression loss) and as the threshold for deciding whether a detection counts as a true positive during evaluation. Related: anchor boxes, NMS, mAP
NMS (Non-Maximum Suppression) — Post-processing step that removes duplicate/overlapping detections of the same object: keep the highest-confidence box, suppress others with IoU above a threshold against it, repeat. A classic detection-pipeline bottleneck for latency-critical settings, motivating NMS-free detector designs (e.g. DETR-style set prediction). Related: IoU, anchor boxes, object detection
mAP (mean Average Precision) — The standard object-detection benchmark metric: compute average precision (area under the precision-recall curve) per class at a given IoU threshold, then average across classes (and often across multiple IoU thresholds, e.g. COCO's mAP@[.5:.95]). Related: IoU, precision/recall/F1, PR-AUC

Multimodal & Autonomous Vehicles

BEV (Bird's-Eye-View) Representation — Projecting features from multiple cameras (and optionally LiDAR/radar) into a shared top-down 2D grid anchored in the vehicle's coordinate frame. Solves the multi-camera fusion problem elegantly since all sensors get expressed in one consistent metric space, making downstream detection/tracking/planning simpler. Related: sensor fusion (early/mid/late), ego-motion, occupancy network
Sensor Fusion: Early / Mid / Late — Early fusion combines raw or near-raw sensor data before feature extraction (max information sharing, but sensitive to calibration/sync errors and hard to scale to modality-specific architectures). Late fusion runs separate pipelines per modality and combines only final outputs/detections (robust, modular, but loses cross-modal signal that could help disambiguate hard cases). Mid (feature-level) fusion combines learned features partway through, and is the common sweet spot in modern AV encoders — e.g. fusing BEV-projected camera and LiDAR features before the detection head. Related: BEV representation, cross-attention, multimodal encoder
Camera Characteristics — Dense, high-resolution semantic/texture information (color, text, classification cues) but no direct depth — depth must be inferred (monocular) or triangulated (stereo/multi-view), and performance degrades in low light, glare, rain, and occlusion. Related: LiDAR characteristics, radar characteristics, sensor fusion
LiDAR Characteristics — Direct, accurate 3D geometry via time-of-flight laser ranging, largely lighting-invariant, but sparse (especially at range), gives no color/texture/semantic information on its own, and is comparatively expensive and mechanically complex. Related: camera characteristics, point-cloud networks, voxelization
Radar Characteristics — Directly measures velocity via Doppler shift (unique among the three), works well in rain/fog/darkness where camera and LiDAR degrade, and has long range — but very low spatial/angular resolution, making object shape and fine localization poor without fusion. Related: camera characteristics, LiDAR characteristics, ego-motion
PointNet — A neural architecture that consumes raw, unordered 3D point sets directly (no voxelization needed) using per-point shared MLPs followed by a permutation-invariant symmetric aggregation (max pooling), so output is invariant to point ordering. Foundational for later point-cloud detection/segmentation architectures. Related: point-cloud networks, voxelization, LiDAR characteristics
Voxelization — Discretizing a 3D point cloud into a regular grid of volumetric cells (voxels), each summarizing the points inside it — enables applying standard 3D (or sparse 3D) convolutions to point-cloud data at the cost of quantization error and cubic memory growth with resolution. Related: pillars, PointNet, point-cloud networks
Pillars (PointPillars-style) — A voxelization variant that discretizes only in the ground-plane (x, y) dimensions into tall vertical "pillars," collapsing the z-dimension per pillar with a learned encoder — cheaper than full 3D voxelization and naturally produces a BEV-aligned feature map, a common LiDAR frontend for AV detection. Related: voxelization, BEV representation, point-cloud networks
CLIP-style Alignment — Contrastively pretraining an image encoder and a text encoder jointly so matching image-caption pairs land close together in a shared embedding space and mismatched pairs land far apart — yields strong zero-shot classification/retrieval and is the standard backbone for connecting vision features to language in VLMs. Related: contrastive learning, VLM, cross-attention
VLM (Vision-Language Model) — A model that jointly processes images and text, typically a vision encoder (often CLIP-style or ViT) whose output features are projected into a language model's token/embedding space so it can reason over and generate text conditioned on visual input. Related: CLIP-style alignment, VLA, cross-attention
VLA (Vision-Language-Action Model) — Extends a VLM by adding an action output head/decoder, so the model maps (image, language instruction) directly to robot/vehicle control outputs — the emerging paradigm for end-to-end embodied policies, including some AV planning stacks. Related: VLM, world model, ego-motion
World Model — A learned model of environment dynamics that predicts future states (often future sensor observations or latent representations) conditioned on actions — used for planning by simulating rollouts internally, and for self-supervised pretraining by predicting future frames from past ones. Related: VLA, temporal fusion, self-supervised learning
Occupancy Network — Predicts, for a dense 3D (or BEV) grid around the vehicle, the probability that each cell is occupied (and often by what class/with what velocity) — a more general representation than discrete bounding-box detection, since it naturally handles arbitrary/unknown-class obstacles ("general-purpose obstacle" detection), a key AV safety property. Related: BEV representation, U-Net, sensor fusion
Temporal Fusion — Combining information across multiple time steps (consecutive frames/sweeps) rather than processing each instant independently — improves detection of occluded/fast-moving objects, reduces flicker, and is essential for velocity/trajectory estimation. Implemented via recurrence, temporal attention, or simple feature-map warping+concatenation across frames. Related: world model, ego-motion, BEV representation
Ego-Motion — The vehicle's own motion (position/velocity/pose change) over time, estimated from IMU, wheel odometry, and/or visual/LiDAR odometry. Must be accounted for when fusing sensor data across time (temporal fusion) since the vehicle's own reference frame is constantly shifting. Related: temporal fusion, BEV representation, sensor fusion
Sensor Calibration (Intrinsics / Extrinsics) — Intrinsics describe a sensor's internal geometry (camera focal length, principal point, lens distortion); extrinsics describe each sensor's pose (rotation + translation) relative to a common vehicle frame. Fusion architectures implicitly assume good calibration — miscalibration is a common, hard-to-diagnose source of degraded fused perception. Related: sensor fusion (early/mid/late), ego-motion, BEV representation
Sim-to-Real Gap — The performance drop when a model trained (partly or fully) in simulation is deployed on real sensor data, caused by simulators imperfectly modeling real sensor noise, lighting, and material properties. Narrowed via domain randomization, real-data fine-tuning, or generative sensor-realism models. Related: domain adaptation/randomization, distribution shift, data augmentation
Perception vs. Prediction vs. Planning — The classic AV stack decomposition: perception detects/tracks what's in the scene now (objects, lanes, occupancy); prediction forecasts how those agents will move over the next few seconds; planning decides the ego vehicle's own trajectory given that forecast. End-to-end/VLA approaches blur these boundaries by learning a more direct observation-to-action mapping, trading interpretability for potentially better joint optimization. Related: world model, VLA, ego-motion
Trajectory Prediction — Forecasting the future path(s) of other agents (vehicles, pedestrians, cyclists) given their observed history and scene context — typically multimodal (an agent might turn left or go straight), so models often output a distribution over plausible future trajectories rather than a single path. Related: world model, temporal fusion, perception vs. prediction vs. planning
HD Map — A high-definition, centimeter-accurate prior map encoding lane geometry, traffic-control locations, and road topology, used as a strong structural prior for perception, prediction, and planning — reduces the burden on real-time perception but requires costly mapping/maintenance and creates a dependency on map freshness. Related: BEV representation, perception vs. prediction vs. planning
