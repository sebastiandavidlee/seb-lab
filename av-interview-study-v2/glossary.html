Glossary & Concept Map

Click any node to jump to its definition. Every term links to its neighbors — the map is the mental model the interview loop tests.

Fundamentals

Bias–variance decomposition — Expected squared error at a point splits exactly into bias² (systematic error of the average predictor) + variance (sensitivity to the training sample) + irreducible noise. High bias means the hypothesis class is too rigid (underfitting); high variance means the fit tracks sampling noise (overfitting). Related: overfitting, regularization, generalization gap
Overfitting / underfitting — Overfitting: training loss keeps falling while validation loss rises, because the model fits noise or spurious correlations. Underfitting: both stay high because capacity or optimization is insufficient. Diagnose with learning curves, fix with more data, regularization, or capacity changes respectively. Related: bias–variance decomposition, regularization
Generalization gap — The difference between training and held-out error. It shrinks with more data and effective regularization and grows with model capacity relative to dataset size; a large gap is the operational definition of overfitting. Related: overfitting, bias–variance decomposition, cross-validation
Regularization (L1 / L2) — Penalties added to the loss to constrain the hypothesis class. L2 (ridge / weight decay) shrinks weights smoothly toward zero and is equivalent to a Gaussian prior; L1 (lasso) induces exact sparsity (Laplace prior). Both reduce variance at the cost of some bias. Related: bias–variance decomposition, weight decay, dropout, data augmentation
Cross-entropy loss — \(-\sum_c y_c \log \hat p_c\); for one-hot labels it is the negative log-likelihood of the true class, and minimizing it minimizes KL divergence from the label distribution to the predicted one. Paired with softmax it yields the clean gradient \(\hat p - y\) on the logits. Related: softmax, maximum likelihood, InfoNCE, label smoothing
Softmax — Maps logits to a probability distribution: \(\hat p_i = e^{z_i/T}/\sum_j e^{z_j/T}\). Temperature \(T\) controls sharpness: \(T\to 0\) approaches argmax, large \(T\) flattens; it is invariant to adding a constant to all logits (used for numerical stability via the max-subtraction trick). Related: cross-entropy loss, calibration, distillation, logistic regression
Logistic regression — Linear model with a sigmoid link, trained by maximizing Bernoulli likelihood (equivalently minimizing binary cross-entropy); its loss is convex, so gradient descent finds the global optimum. The go-to baseline and the standard warm-up in ML-fundamentals rounds. Related: cross-entropy loss, convexity, softmax, maximum likelihood
Maximum likelihood estimation (MLE) — Choose parameters that maximize the probability of the observed data; for classification this is exactly cross-entropy minimization. Adding a prior gives MAP estimation, whose log-prior term appears as a regularizer (Gaussian prior ↔ L2). Related: cross-entropy loss, regularization
Precision / recall — Precision = TP/(TP+FP): of what I flagged, how much was right. Recall = TP/(TP+FN): of what exists, how much I found. They trade off along the decision threshold; which one dominates depends on the cost of false alarms vs misses (in AV perception, missed pedestrians vs phantom braking). Related: PR-AUC vs ROC-AUC, F1 score, decision threshold, confusion matrix
PR-AUC vs ROC-AUC — ROC-AUC plots TPR vs FPR and equals the probability a random positive outscores a random negative; because FPR is normalized by the (huge) negative count, it looks deceptively good under heavy class imbalance. PR-AUC replaces FPR with precision, which directly exposes the false-positive load per detection, so prefer it for rare-positive problems like open-road obstacle classes. Related: precision / recall, class imbalance, mAP
F1 score — Harmonic mean of precision and recall, \(2PR/(P+R)\); punishes whichever is worse. F\(_\beta\) generalizes it by weighting recall \(\beta\) times as much as precision — pick \(\beta>1\) when misses are costlier. Related: precision / recall, decision threshold
Confusion matrix — The full count table of predicted vs true classes; every threshold metric (precision, recall, FPR, accuracy) is a ratio of its cells. In multiclass settings the off-diagonal structure tells you which classes are confusable — the starting point of any error analysis. Related: precision / recall, error analysis
Decision threshold — The score cutoff that turns a probabilistic classifier into decisions; sweeping it traces the ROC/PR curves. The optimal threshold is set by relative misclassification costs and the class prior, not fixed at 0.5 — a key point when costs are asymmetric. Related: precision / recall, calibration, class imbalance
Calibration — A model is calibrated if predicted confidence matches empirical frequency (of predictions at 0.8, ~80% are correct); measured with reliability diagrams and Expected Calibration Error (ECE). Modern deep nets are typically overconfident; temperature scaling — fitting one scalar \(T\) on validation logits — is the standard cheap fix. Calibrated scores matter whenever downstream logic thresholds on confidence. Related: softmax, decision threshold, ECE
Class imbalance — When class frequencies are highly skewed (the norm in AV: vast background, rare vulnerable road users), accuracy and ROC-AUC mislead and the loss is dominated by the majority class. Remedies: re-sampling, loss re-weighting, focal loss, hard-negative mining, and evaluating with PR-based metrics per class. Related: focal loss, PR-AUC vs ROC-AUC, hard-negative mining, long tail
Long-tail distribution — Real driving data has a few dominant scenarios and an enormous tail of rare ones; average metrics saturate while tail performance stalls. Handling the tail — targeted mining, synthetic data, per-slice evaluation — is where AV data engines earn their keep. Related: class imbalance, active learning, data engine, synthetic data
Train / validation / test split — Train fits parameters, validation selects hyperparameters and checkpoints, test estimates final generalization exactly once. Leakage — correlated samples straddling the split (e.g. frames from the same drive) — silently inflates every metric, so split by drive/scene, not by frame. Related: generalization gap, data leakage
Data leakage — Any path by which information about the evaluation target reaches training: temporal overlap, duplicated scenes across splits, labels derived from features. Symptom: offline metrics far above online performance. Related: train / validation / test split, distribution shift
Feature normalization — Standardizing inputs (zero mean, unit variance) conditions the loss surface so one learning rate fits all directions; unnormalized features stretch the quadratic bowl and slow gradient descent — the same ill-conditioning story as a large condition number. Related: condition number, batch normalization, gradient descent
Convexity — A function where every chord lies above the graph; gradient descent on a convex loss converges to the global optimum. Logistic regression and quadratics are convex; deep nets are not, yet SGD finds good minima anyway — a standard discussion point. Related: gradient descent, quadratic bowl, logistic regression

Training & Scaling

Gradient descent — Iterate \(\theta_{t+1} = \theta_t - \eta \nabla L(\theta_t)\), moving against the local gradient. On a quadratic \(\tfrac12\theta^\top A\theta\) it converges iff \(\eta < 2/\lambda_{\max}(A)\), and the convergence rate is governed by the condition number — exactly the behavior the pure-Python coding round probes. Related: SGD, learning rate, condition number, convexity
Learning rate — The single most important hyperparameter: too small crawls, too large oscillates or diverges (on a quadratic, divergence begins exactly at \(\eta = 2/\lambda_{\max}\)). Deep nets typically use warmup then decay rather than a constant. Related: gradient descent, LR schedule, condition number
Condition number — \(\kappa = \lambda_{\max}/\lambda_{\min}\) of the Hessian; large \(\kappa\) means a narrow valley where the stable learning rate is set by the steep direction while progress along the shallow one is \(\kappa\times\) slower. Motivates momentum, preconditioning (Adam), and feature normalization. Related: gradient descent, momentum, AdamW, feature normalization
SGD (stochastic gradient descent) — Gradient descent on minibatch estimates of the gradient; the noise makes each step cheap, enables huge datasets, and acts as implicit regularization. Convergence needs a decaying or scheduled learning rate because gradient noise never vanishes at the optimum. Related: gradient descent, batch size, momentum, LR schedule
Momentum — Accumulate an exponential moving average of gradients (velocity) and step along it; damps oscillation across the narrow axis of a valley while accelerating along the shallow one, improving the effective condition-number dependence from \(\kappa\) to \(\sqrt{\kappa}\). Related: SGD, condition number, AdamW
Adam / AdamW — Adam scales each coordinate's step by first/second gradient-moment estimates — a diagonal preconditioner that tolerates ill-conditioning. AdamW decouples weight decay from the adaptive gradient update (true L2 shrinkage rather than a rescaled loss penalty) and is the default for transformer training. Related: momentum, weight decay, condition number, LR schedule
Learning-rate schedule — Warmup (linear ramp over the first steps, stabilizing early training when gradients and Adam moment estimates are unreliable) followed by decay, usually cosine, to a small floor. Standard for transformers; changing batch size means rescaling the peak LR. Related: learning rate, batch size, AdamW
Batch size & linear scaling rule — Larger batches lower gradient noise and raise hardware utilization; the linear scaling rule (LR ∝ batch size, with warmup) preserves training dynamics up to a critical batch size, beyond which returns diminish and generalization can suffer without tuning. Related: SGD, LR schedule, data parallelism
Weight decay — Multiplicative shrinkage of weights each step; identical to L2 regularization for plain SGD but not for adaptive optimizers — hence AdamW's decoupling. Controls effective capacity and interacts with the LR schedule. Related: regularization, AdamW
Dropout — Randomly zero activations during training (rescaling at test time), preventing co-adaptation and acting like an implicit ensemble of subnetworks. Less common in modern large-scale vision pretraining, where data scale and augmentation regularize instead. Related: regularization, data augmentation
Batch normalization — Normalize each channel by minibatch statistics, then learn scale/shift; smooths optimization and allows larger LRs. Gotchas: behavior differs train vs eval (running stats), and it couples examples within a batch — problematic for small batches and detection fine-tuning. Related: layer normalization, feature normalization
Layer normalization — Normalize across the feature dimension per token, independent of batch — which is why transformers use it (variable batch/sequence, no train/eval mismatch). Pre-norm placement (LN before attention/MLP) is standard for stable deep-transformer training. Related: batch normalization, ViT, self-attention
Data augmentation — Label-preserving input transforms (crops, flips, color jitter, CutMix; for point clouds: rotation, scaling, ground-truth paste) that encode invariances and multiply effective data. It is regularization through the data rather than the loss. Related: regularization, self-supervised learning, domain randomization
Label smoothing — Replace one-hot targets with \((1-\epsilon)\) on the true class and \(\epsilon/(C-1)\) elsewhere; prevents unbounded logit growth, improves calibration, and slightly regularizes — at the cost of distorting the true conditional distribution. Related: cross-entropy loss, calibration, distillation
Focal loss — Cross-entropy scaled by \((1-\hat p_t)^\gamma\), down-weighting well-classified (mostly easy-negative) examples so the vast background in dense detection doesn't drown out rare positives. Introduced with RetinaNet; \(\gamma=2\) is the usual default. Related: class imbalance, cross-entropy loss, hard-negative mining
Hard-negative mining — Preferentially train on the negatives the current model gets wrong (highest-loss background regions, near-miss lookalikes); a sampling-side alternative to focal loss for the same imbalance problem, and a core loop in AV data engines. Related: focal loss, class imbalance, active learning
Active learning — Spend the labeling budget on the most informative samples — selected by model uncertainty, ensemble disagreement, or embedding-space novelty — instead of labeling uniformly. At fleet scale this is the auto-triage layer deciding which of millions of clips deserve human labels. Related: data engine, long-tail distribution, hard-negative mining
Data engine — The closed loop that turns fleet data into model improvements: deploy → detect failures/novelty → mine similar cases → label (human or auto) → retrain → redeploy. The defining infrastructure of AV ML organizations; models are downstream of it. Related: active learning, auto-labeling, long-tail distribution
Auto-labeling — Use large offline models with no latency constraints — bigger backbones, temporal smoothing over full clips, multi-sensor late fusion — to generate labels that train the small online model; effectively distillation through the dataset. Related: data engine, distillation, pseudo-labeling
Self-supervised learning (SSL) — Pretrain on unlabeled data via pretext objectives: contrastive (InfoNCE), self-distillation (DINO), or masked reconstruction (MAE). Decouples representation learning from labels — decisive for AV, where raw fleet data is nearly free but labels are not. Related: InfoNCE, CLIP, foundation model, transfer learning
Transfer learning / fine-tuning — Initialize from a pretrained backbone and adapt: linear probe (frozen features), full fine-tune, or parameter-efficient methods (LoRA). The standard answer to "small labeled dataset, hard task"; expect to discuss what to freeze and why. Related: self-supervised learning, LoRA, foundation model
LoRA (low-rank adaptation) — Freeze pretrained weights and learn low-rank additive updates \(\Delta W = BA\); trains a few percent of parameters, cuts optimizer memory, and the update merges into the base weights at inference with zero overhead. Related: transfer learning, fine-tuning, foundation model
Scaling laws — Loss falls as a power law in model size, data, and compute; compute-optimal training balances parameters and tokens (Chinchilla: roughly ~20 tokens per parameter for LLMs). The interview use: justify whether the next dollar goes to more data, a bigger model, or longer training. Related: foundation model, data engine, distillation
Data / model parallelism (DDP, FSDP) — DDP replicates the model and all-reduces gradients per step (communication ∝ model size); when the model outgrows one GPU, FSDP/ZeRO shard parameters, gradients, and optimizer states, and tensor/pipeline parallelism split the computation itself. Related: batch size, mixed precision, scaling laws
Mixed precision (FP16/BF16) — Compute in 16-bit with FP32 master weights/accumulations, using tensor cores for ~2× throughput and half the activation memory. FP16 needs loss scaling to avoid gradient underflow; BF16 keeps FP32's exponent range and usually needs none. Related: quantization, TensorRT, data parallelism

Inference & Deployment

Quantization — Map float weights/activations to low-bit integers via a scale (and zero-point): \(x \approx s\,(q - z)\). Cuts memory and bandwidth ~4× (INT8) and exploits fast integer units; the craft is choosing granularity (per-tensor vs per-channel) and handling outliers so accuracy survives. Related: PTQ vs QAT, AWQ, mixed precision, distillation
PTQ vs QAT — Post-training quantization converts a trained model using a small calibration set to fit scales — cheap, no retraining, usually fine at INT8. Quantization-aware training inserts fake-quant ops so training adapts to the rounding (via straight-through gradients) — costlier but recovers accuracy at aggressive bit-widths (INT4) or on sensitive layers. Related: quantization, AWQ, calibration
AWQ (activation-aware weight quantization) — PTQ method built on the observation that a small fraction of weight channels are salient because their activations are large. Instead of keeping them in FP16, AWQ scales salient channels up before quantization (folding the inverse into the adjacent layer), shrinking their relative rounding error — near-FP16 quality at INT4 with no retraining. Related: quantization, PTQ vs QAT, distillation
Knowledge distillation — Train a small student to match a large teacher's temperature-softened output distribution (and optionally intermediate features); the soft targets carry inter-class similarity structure that hard labels lack. The main route from offline foundation models to deployable onboard networks. Related: auto-labeling, quantization, softmax, ensembling
Pruning — Remove weights or whole structures. Unstructured sparsity rarely speeds up dense hardware without special support (e.g. NVIDIA 2:4 semi-structured sparsity); structured pruning (channels, heads, layers) gives real latency wins but needs fine-tuning to recover accuracy. Related: distillation, quantization, latency vs throughput
ONNX / graph export — Serialize the model as a static operator graph decoupled from Python, enabling compilers like TensorRT to consume it. Classic pain points: unsupported ops, dynamic shapes, and control flow that traces incorrectly. Related: TensorRT, operator fusion
TensorRT / inference compilers — Compile the graph for a target GPU: fuse operators, pick fastest kernels per shape, apply FP16/INT8, and emit a fixed engine. Typically the single biggest deployment speedup after quantization; torch.compile plays a similar role in-framework. Related: operator fusion, quantization, ONNX, latency vs throughput
Operator fusion — Merge adjacent ops (conv+BN+ReLU, attention chains) into one kernel so intermediates stay in registers instead of round-tripping through HBM; attacks memory-bound ops where bandwidth, not FLOPs, is the limit. Related: TensorRT, arithmetic intensity, memory-bound vs compute-bound
Latency vs throughput — Latency: time for one input end-to-end; throughput: inputs/second in aggregate. Batching raises throughput but adds queueing latency; an AV stack is latency-bound (fixed per-frame budget at e.g. 10–30 Hz, tail latency matters more than mean), whereas offline auto-labeling is throughput-bound. Related: TensorRT, real-time budget
Memory-bound vs compute-bound — An op is memory-bound when bytes moved, not FLOPs, set its runtime (elementwise ops, small-batch matmuls, LLM decode) and compute-bound when arithmetic dominates (large convs/matmuls). Diagnosis dictates the fix: fusion/quantization for bandwidth, lower-precision math or fewer FLOPs for compute. Related: arithmetic intensity, roofline model, operator fusion
Arithmetic intensity — FLOPs per byte of memory traffic. Compare it to the hardware's FLOPs/bandwidth ratio: below the ridge point you're bandwidth-limited, above it compute-limited — the one number that predicts whether quantization or a faster ALU helps. Related: roofline model, memory-bound vs compute-bound
Roofline model — Plot attainable FLOP/s vs arithmetic intensity: a bandwidth-sloped roof meeting a flat compute ceiling. Placing each layer on the roofline tells you its headroom and which optimizations can possibly pay off. Related: arithmetic intensity, memory-bound vs compute-bound
KV cache — Store past keys/values so autoregressive decoding is O(1) new-token attention instead of recomputing the prefix; makes decode memory-bandwidth-bound and is the memory driver for long contexts. Relevant wherever transformer decoders run under a latency budget. Related: self-attention, memory-bound vs compute-bound, quantization
Edge deployment constraints — Onboard compute is fixed for the vehicle's life: hard power/thermal envelopes, safety-rated SoCs, deterministic scheduling, and redundancy requirements. Design implication: the offline/online model split — heavy models feed the data engine, distilled ones drive. Related: distillation, quantization, latency vs throughput, data engine
Profiling — Measure before optimizing: per-kernel timelines (Nsight, torch profiler) reveal whether time goes to compute, memory, launch overhead, or host-side stalls. The interview-safe stance: never claim a speedup without a profile and a benchmark. Related: memory-bound vs compute-bound, TensorRT
Shadow mode / staged rollout — Run the candidate model in parallel with production without acting on its outputs, comparing decisions at fleet scale before promotion; the deployment-side answer to "how do you know the new model is safe?" Related: data engine, distribution shift, evaluation slices
Distribution shift / OOD — Deployment data drifts from training data (new geography, weather, sensor change); offline metrics stop predicting online behavior. Detect via monitoring, embedding-space novelty, and per-slice regressions; fix through the data engine. Related: data engine, domain randomization, shadow mode
Evaluation slices — Report metrics per meaningful subset (night, rain, occluded pedestrians, range bands) rather than one aggregate; aggregate metrics hide tail regressions that matter most for safety sign-off. Related: long-tail distribution, distribution shift, mAP

Architectures

CNN (convolutional network) — Learn local filters shared across positions: translation equivariance and locality as built-in inductive bias, giving strong sample efficiency on images. Still the workhorse for high-rate, low-latency AV backbones even as attention takes over fusion layers. Related: receptive field, ResNet, ViT, inductive bias
Receptive field — The input region influencing one output activation; grows with depth, stride, and dilation. Detecting large or distant objects requires sufficient receptive field — a classic reason to add FPN levels or global attention. Related: CNN, FPN, self-attention
ResNet / residual connections — Reformulate layers as identity + residual \(x + F(x)\), giving gradients a direct path and making very deep networks trainable; residual streams are now universal, including in every transformer block. Related: CNN, ViT, layer normalization
FPN (feature pyramid network) — Top-down pathway with lateral connections that spreads deep semantics onto high-resolution shallow features, producing a multi-scale pyramid so detectors handle small and large objects with one backbone. Related: receptive field, anchors, DETR
ViT (Vision Transformer) — Split the image into fixed patches, linearly embed them into tokens, add positional encodings, and run a standard transformer encoder. Weaker inductive bias than CNNs, so it wins with large-scale (self-supervised) pretraining; global attention from layer one. Related: patch embedding, tokens, self-attention, CLIP
Patch embedding — The image tokenizer: a P×P patch flattened and linearly projected to model dimension (equivalently a stride-P conv). Token count = (H/P)(W/P), so patch size sets the compute/resolution tradeoff — attention cost scales with its square. Related: ViT, tokens, positional encoding
Tokens — The transformer's universal currency: fixed-dimension vectors in a set/sequence. Any modality becomes tokens — image patches, LiDAR pillars, radar returns, map polylines, text — which is precisely what makes one fusion backbone over heterogeneous AV sensors possible. Related: patch embedding, self-attention, BEV, sensor fusion
Self-attention — Each token forms query/key/value projections; outputs are value sums weighted by \(\mathrm{softmax}(QK^\top/\sqrt{d_k})\). Content-based global routing with O(n²) cost in token count — the reason token budgets and deformable/sparse variants exist. Related: multi-head attention, cross-attention, tokens, KV cache
Multi-head attention — Run h attention operations in parallel on d/h-dimensional projections and concatenate; heads attend to different relation types (position-like, semantic-like) without extra parameter cost over single-head at equal width. Related: self-attention, cross-attention
Cross-attention — Queries come from one set, keys/values from another — the canonical mechanism for asymmetric fusion: BEV queries attending to camera features, DETR object queries attending to the image, decoders attending to encoders. Related: self-attention, BEV, DETR, sensor fusion
Positional encoding — Attention is permutation-invariant, so position must be injected: sinusoidal or learned embeddings added to tokens, or rotary (RoPE) applied inside attention. In BEV models, 3D coordinate-based positional encodings tie image tokens to geometry. Related: tokens, self-attention, BEV
Encoder vs decoder (transformer) — Encoders use bidirectional self-attention to produce representations (ViT, BERT); decoders use causal self-attention plus cross-attention to generate or to refine query sets (GPT, DETR's decoder). Perception stacks are mostly encoders with query-based decoder heads. Related: self-attention, cross-attention, DETR
Anchor-based vs anchor-free detection — Anchor-based heads classify/regress from predefined prior boxes at each location (Faster R-CNN, RetinaNet); anchor-free heads predict from points or centers directly (FCOS, CenterPoint). Anchor-free removes prior tuning and transfers cleanly to 3D/BEV detection. Related: DETR, NMS, FPN, 3D object detection
DETR (detection transformer) — Detection as set prediction: learned object queries cross-attend to image features and output boxes directly, trained with Hungarian (bipartite) matching so each ground truth pairs with exactly one prediction — eliminating NMS and anchors. Deformable DETR fixed its slow convergence and small-object weakness. Related: cross-attention, deformable attention, NMS, anchors
NMS (non-maximum suppression) — Greedy post-process removing detections that overlap a higher-scoring one above an IoU threshold; needed because dense heads predict duplicates. Set-prediction models (DETR family) make it unnecessary by construction. Related: DETR, IoU, anchors
IoU (intersection over union) — Overlap area divided by union area between boxes/masks; the matching criterion in detection metrics and NMS. GIoU/DIoU variants keep a useful gradient when boxes don't overlap; 3D IoU adds height and yaw. Related: mAP, NMS, 3D object detection
mAP (mean average precision) — Area under the precision-recall curve per class at a given IoU-matching threshold, averaged over classes (COCO also averages over IoU 0.5:0.95). The standard detection metric; nuScenes replaces IoU-matching with center-distance and adds per-attribute error terms. Related: PR-AUC vs ROC-AUC, IoU, evaluation slices
U-Net / dense prediction — Encoder-decoder with skip connections from each resolution to its mirror, preserving fine detail for per-pixel outputs (segmentation, depth, occupancy heads). The default shape for dense decoding on top of any backbone. Related: FPN, occupancy, ResNet
Inductive bias — Assumptions built into the architecture (convolutional locality, attention's permutation invariance, geometric constraints in BEV lifting). Stronger bias buys sample efficiency; weaker bias plus more data buys asymptotic performance — the framing device for CNN-vs-ViT questions. Related: CNN, ViT, scaling laws
Embedding — A learned vector representation where task-relevant similarity becomes geometric proximity; the substrate for retrieval, contrastive learning, novelty mining, and open-vocabulary matching. Related: InfoNCE, CLIP, tokens
Foundation model — A large model pretrained on broad data that adapts to many downstream tasks (fine-tuning, prompting, distillation). In AV: pretrain a multimodal encoder on fleet-scale unlabeled sensor data, then specialize per task — the premise of the target team. Related: self-supervised learning, scaling laws, distillation, transfer learning

Multimodal & AV

BEV (bird's-eye view) — A top-down metric grid around the ego vehicle used as the shared representation: every sensor projects into it, features fuse naturally in space, and downstream planning consumes it directly. The central design decision in a multimodal perception encoder is how each modality gets lifted into BEV. Related: LSS, deformable attention, sensor fusion, occupancy
LSS (Lift-Splat-Shoot) — Camera-to-BEV lifting via explicit depth: each pixel predicts a categorical depth distribution, features are outer-product-weighted along the ray into a frustum point cloud ("lift"), then sum-pooled into BEV cells ("splat"). Fully geometric and differentiable; accuracy is bounded by depth-estimate quality, and the dense frustum is memory-heavy. Related: BEV, deformable attention, camera intrinsics / extrinsics
Deformable attention — Each query attends to a small learned set of sampling offsets around a reference point instead of all tokens — linear rather than quadratic cost. In BEVFormer-style lifting, each BEV cell projects its 3D pillar into the images and deformably samples there: attention-based lifting without dense depth, the main alternative to LSS. Related: BEV, LSS, cross-attention, DETR
Temporal fusion — Aggregate features across frames — warping past BEV features by ego-motion and fusing recurrently or via temporal attention. Buys velocity estimation, occlusion persistence, and stability; the catch is correct ego-motion alignment of moving objects. Related: BEV, ego-motion compensation, tracking
Sensor fusion (early / mid / late) — Early: fuse raw data (paint LiDAR points with pixels) — maximal information, brittle to calibration and sensor dropout. Late: fuse per-sensor detections — robust and modular, but errors are baked in. Mid-level (feature) fusion in a shared space like BEV is the modern default, keeping cross-modal evidence while tolerating asynchrony. Related: BEV, cross-attention, camera intrinsics / extrinsics, tokens
Camera intrinsics / extrinsics — Intrinsics K (focal lengths, principal point) map camera-frame 3D to pixels; extrinsics [R|t] place the camera in the vehicle/world frame; together \(u \sim K[R|t]X\). Every geometric lifting method consumes these, so online calibration drift is a genuine failure mode worth naming in design rounds. Related: LSS, sensor fusion, ego-motion compensation
LiDAR point cloud — Sparse, unordered 3D returns with precise range but density falling off with distance and degradation in rain/fog/snow. Processing requires order-invariant operators — voxelization, pillars, or point-based networks — rather than dense grids. Related: voxelization / PointPillars, sensor fusion, 3D object detection
Voxelization / PointPillars — Regularize point clouds by binning into 3D voxels (processed with sparse 3D convs) or vertical pillars (PointNet per pillar → a 2D BEV pseudo-image processed by fast 2D convs). PointPillars trades some vertical resolution for real-time speed — the standard latency/accuracy fork. Related: LiDAR point cloud, BEV, 3D object detection
Radar — Directly measures range and radial velocity (Doppler) and works in weather that blinds cameras and LiDAR, but returns are sparse, noisy, and poor in elevation. Typically fused as complementary velocity/robustness evidence rather than a primary geometry source. Related: sensor fusion, tracking, BEV
3D object detection — Predict 7-DoF boxes (x, y, z, l, w, h, yaw) plus class and often velocity, in the ego/BEV frame. Camera-only variants hinge on depth quality; LiDAR-based (CenterPoint) dominate range accuracy; fusion approaches take both. Evaluated with 3D IoU or center-distance mAP. Related: BEV, IoU, mAP, voxelization / PointPillars
Occupancy prediction — Predict per-voxel occupied/free (and semantics) around the ego vehicle instead of only boxes; handles irregular and unknown-category obstacles that box detectors structurally miss. The modern dense complement to 3D detection heads on a BEV/voxel backbone. Related: BEV, 3D object detection, U-Net / dense prediction
Multi-object tracking (MOT) — Maintain object identities over time: associate detections to tracks (Hungarian matching on motion/appearance affinity) and filter state (Kalman). Tracking-by-detection remains the deployed default; query-based trackers carry track queries through the transformer instead. Related: temporal fusion, 3D object detection, trajectory prediction
Ego-motion compensation — Transform past sensor data/features into the current ego frame using odometry, so temporal aggregation compares the same world locations; without it, temporal fusion smears static structure. Correct for static scene, approximate for movers. Related: temporal fusion, camera intrinsics / extrinsics, tracking
InfoNCE — Contrastive objective: cross-entropy of picking the true positive pair among a batch of negatives, \(-\log \frac{e^{s(x,y^+)/\tau}}{\sum_i e^{s(x,y_i)/\tau}}\), with cosine similarity \(s\) and temperature \(\tau\). Maximizes a lower bound on mutual information; the engine of CLIP and most cross-modal alignment, and it needs large effective batch sizes for hard negatives. Related: CLIP, cross-entropy loss, self-supervised learning, embedding
CLIP — Dual image/text encoders trained with symmetric InfoNCE on web-scale pairs, yielding a shared embedding space that enables zero-shot classification and open-vocabulary detection heads. In AV: language-queryable data mining and open-set recognition; the template for aligning any two modalities. Related: InfoNCE, ViT, open-vocabulary, embedding
Open-vocabulary perception — Replace a fixed class list with language embeddings as the classifier, so novel categories are matched by text at inference. Attacks the long-tail taxonomy problem: you cannot pre-enumerate everything a car will meet. Related: CLIP, long-tail distribution, embedding
Cross-modal alignment — Pretrain by pulling together embeddings of the same scene from different sensors (image crop ↔ LiDAR region), using calibration for correspondence; gives label-free multimodal pretraining and a shared space where a missing modality can be partially substituted. Related: InfoNCE, CLIP, sensor fusion, self-supervised learning
Pseudo-labeling — Train on model-generated labels for unlabeled data, filtered by confidence; the semi-supervised core of auto-labeling pipelines. Failure mode: confirmation bias — the student inherits the teacher's blind spots, so keep human audits on the tail. Related: auto-labeling, distillation, active learning
Synthetic data — Simulated or generated sensor data with free perfect labels; the practical answer for rare/dangerous scenarios you cannot collect. The catch is the sim-to-real gap in both appearance and label distribution — close it with domain randomization, style transfer, or mixing ratios validated on real slices. Related: domain randomization, sim-to-real gap, long-tail distribution
Domain randomization — Randomize simulator nuisance factors (textures, lighting, weather, sensor noise) so aggressively that the real world looks like just another sample; buys transfer without photorealism by forcing invariance to what was randomized. Related: synthetic data, sim-to-real gap, data augmentation
Sim-to-real gap — The performance drop moving from simulation to reality, from mismatched appearance, physics, and scenario statistics. Measure it explicitly (same model, sim vs real eval) before trusting any simulation-derived conclusion. Related: synthetic data, domain randomization, distribution shift
HD map / online mapping — Offline HD maps give centimeter lane geometry as a prior but cost maintenance and fail when stale; online vectorized mapping (MapTR-style: map elements as point-set queries decoded from BEV) infers lanes on the fly. The industry trend is map-lite with online perception carrying more load. Related: BEV, DETR, trajectory prediction
Trajectory prediction — Forecast distributions over agent futures conditioned on track history, map, and interactions; inherently multimodal (yield vs go), so models output multiple weighted hypotheses. Consumes perception outputs — its quality ceiling is set by upstream detection and tracking. Related: tracking, HD map, occupancy
End-to-end driving — Train perception-through-planning jointly (UniAD-style modular E2E, or sensor-to-trajectory models) so intermediate representations optimize for the driving objective rather than proxy perception metrics. Tension to articulate: performance and simplicity vs interpretability and safety validation. Related: BEV, foundation model, trajectory prediction
VLA (vision-language-action) models — Vision-language backbones fine-tuned to emit actions, transferring open-world semantics to control; the robotics counterpart of the AV foundation-model thesis, sharing its core problems — tokenizing continuous sensor/action spaces and distilling for real-time inference. Related: foundation model, tokens, end-to-end driving, distillation
World model — A generative model of environment dynamics — predict future observations or latent states conditioned on actions; usable as a learned simulator, a pretraining objective, and a closed-loop evaluator for driving policies. Related: synthetic data, end-to-end driving, foundation model
