Classification, from decision boundary to deployment metric

Everything on this page is the machinery under any perception head you have shipped: the per-pixel class scores in a segmentation model, the objectness logit in a detector, the keypoint-visibility flag in your synthetic-data pipeline. The goal is to be able to derive each piece at a whiteboard, not just name it.

1. Problem setup: scores, decisions, and the two modeling families

A classifier is two things stapled together: a score function (continuous, carries confidence) and a decision rule (a threshold on the score). Keep them mentally separate — training shapes the score; the operating point picks the threshold, and it can be picked after training, per deployment. This is exactly the detector-confidence-threshold knob you tune per class in perception stacks.

Two modeling families produce that score:

  • Discriminative: model \(p(y \mid x)\) directly (logistic regression, every softmax neural net). Spends all capacity on the boundary.
  • Generative: model \(p(x \mid y)\,p(y)\) and invert with Bayes (naive Bayes, GMM classifiers). Models the data itself, so it can synthesize, handle missing features, and detect outliers — but wastes capacity on structure the decision never needed.
Intuition. Discriminative asks "which side of the fence is this point on?"; generative asks "which factory produced this point?" — then infers the fence. When data is plentiful, discriminative wins (Ng & Jordan 2002: generative reaches its asymptote faster, but the discriminative asymptote is lower error). Deep classification is almost entirely discriminative.
Memorize
  • decision boundary — the level set where the score crosses the threshold; linear model → hyperplane.
  • discriminative vs generative — \(p(y\mid x)\) vs \(p(x\mid y)p(y)\); Bayes' rule connects them.
  • score vs decision — continuous confidence vs thresholded label; the threshold is a deployment knob, not a training artifact.
  • Bayes error — the irreducible error of the optimal classifier when class distributions overlap.
Related: logit, operating point, likelihood ratio test.
Quiz: score vs decision

Q: You retrained nothing, but false positives on a rare class dropped after a config change. What most likely changed? — The decision threshold (operating point) on that class's score, not the score function itself.

Q: Why can a generative model detect out-of-distribution inputs while a discriminative one usually can't? — It models \(p(x)\), so a low-likelihood input is visible; a discriminative model only ever outputs a conditional over known classes and will confidently pick one.

2. Interactive: logistic regression playground

Logistic regression is a linear score \(z = wx + b\) squashed through the sigmoid \(\sigma(z) = 1/(1+e^{-z})\) so it can be read as a probability. Three things to internalize by playing:

  • b shifts, w sharpens. The boundary sits at \(x^{*} = -b/w\); the slope of the probability ramp is \(w/4\) at the boundary. Large \(|w|\) → confident, step-like classifier.
  • Loss and accuracy diverge. Set the boundary correctly, then crank \(w\) very high: accuracy is unchanged (same decisions) but if even one point is misclassified, cross-entropy explodes — CE punishes confident wrongness. Conversely a tiny \(w\) can have identical accuracy with mushy probabilities and mediocre CE.
  • Accuracy is flat almost everywhere. It only changes when the threshold crosses a data point — a step function with zero gradient. That is why we train on CE and merely report accuracy.
Intuition. Cross-entropy is a smooth, convex surrogate for the 0/1 loss you actually care about. Gradient descent needs slope; accuracy has none. Every "why not optimize the metric directly?" interview question resolves to this picture.
Memorize
  • sigmoid — \(\sigma(z)=1/(1+e^{-z})\); derivative \(\sigma(1-\sigma)\).
  • logit — the pre-sigmoid score \(z\); equals log-odds \(\ln\frac{p}{1-p}\).
  • surrogate loss — smooth stand-in (CE, hinge) for the non-differentiable 0/1 loss.
  • decision threshold — \(p=0.5 \Leftrightarrow z=0 \Leftrightarrow x=-b/w\) in 1-D.
Related: log-odds, convexity of logistic loss, perceptron (its non-probabilistic ancestor).
Quiz: loss vs accuracy

Q: Training loss keeps dropping but validation accuracy is flat. Give one benign explanation. — The model is sharpening probabilities on already-correct examples (CE falls) without moving any decision across the threshold.

Q: In the widget, what setting gives 100% accuracy but terrible CE? Why is it impossible here? — It isn't possible if the classes overlap: any boundary misclassifies someone, and high \(w\) makes their CE term huge. With separable data, CE → 0 as \(w\to\infty\) — which is why separable logistic regression needs regularization to converge.

3. Softmax + cross-entropy: the default output head

Softmax generalizes the sigmoid to \(K\) classes; cross-entropy generalizes logistic loss:

$$p_i = \frac{e^{z_i/\tau}}{\sum_j e^{z_j/\tau}}, \qquad \mathcal{L}_{CE} = -\sum_i y_i \log p_i = -\log p_{\text{true}}$$

Why CE = maximum likelihood: if the model outputs \(p(y\mid x;\theta)\), the negative log-likelihood of the dataset is exactly the summed cross-entropy. Minimizing CE is MLE for a categorical output — that's the principled reason it's the default, not a convention.

The gradient everyone should derive once:

$$\frac{\partial \mathcal{L}_{CE}}{\partial z_i} = p_i - y_i$$

Prediction minus target. Clean, bounded in \([-1,1]\), never saturates the way MSE-through-sigmoid does (whose gradient carries a \(\sigma'(z)\) factor that vanishes for confident-wrong outputs). This composed gradient is the single most-asked derivation in ML fundamentals rounds.

# softmax + CE, numerically stable
import numpy as np
def softmax_ce(z, y):            # z: (K,) logits, y: int label
    z = z - z.max()              # shift-invariance: avoids overflow
    logp = z - np.log(np.exp(z).sum())
    loss = -logp[y]
    p = np.exp(logp)
    grad = p.copy(); grad[y] -= 1.0   # dL/dz = p - y
    return loss, grad
Intuition. Softmax is a smooth argmax with a thermostat. Temperature \(\tau\) rescales logits before the exponential: it changes relative confidence but never the winner. That single fact powers distillation (soften the teacher) and calibration (temperature scaling) — both later on these pages.
Memorize
  • softmax — exponentiate-and-normalize; shift-invariant (\(z + c\) gives same \(p\)), which is also the stability trick.
  • cross-entropy — \(-\log p_{\text{true}}\); equals NLL, so minimizing it is MLE.
  • (p − y) gradient — softmax+CE composed gradient w.r.t. logits.
  • temperature τ — divides logits; sharpens (τ<1) or flattens (τ>1) without changing argmax.
  • label smoothing — replace one-hot \(y\) with \((1-\epsilon)\)-hot; regularizes confidence, slightly mis-calibrates.
Related: KL divergence (CE = entropy + KL), NLL, log-sum-exp.
Quiz: derive it

Q: Derive \(\partial \mathcal{L}/\partial z_i\) for softmax + CE. — Write \(\mathcal{L} = -z_t + \log\sum_j e^{z_j}\) for true class \(t\); differentiate: \(-\mathbb{1}[i{=}t] + p_i = p_i - y_i\).

Q: Why subtract the max before exponentiating? — Softmax is invariant to adding a constant to all logits; subtracting the max makes every exponent ≤ 0, preventing overflow with no change in output.

4. Interactive: bias–variance explorer

The expected test error of a regressor decomposes exactly:

$$\mathbb{E}\big[(y - \hat f(x))^2\big] = \underbrace{\sigma^2}_{\text{irreducible noise}} + \underbrace{\big(\mathbb{E}[\hat f(x)] - f(x)\big)^2}_{\text{bias}^2} + \underbrace{\mathbb{E}\big[(\hat f(x) - \mathbb{E}[\hat f(x)])^2\big]}_{\text{variance}}$$

Bias: error from the hypothesis class being too rigid (degree 1 cannot represent a sine). Variance: error from the fit chasing this particular sample's noise (degree 12 would look wildly different on a re-drawn training set). Capacity trades one for the other; the test-error U is that trade made visible.

Modern caveat worth saying in the interview: heavily over-parameterized deep nets can descend again past the interpolation point ("double descent"), so the classical U is the right mental model for the classical regime and small data, not a universal law. SGD noise, augmentation, and early stopping all act as implicit variance control.

Intuition. Train error measures how well you memorized; test error measures how well you generalized; the gap between the two curves is overfitting. Watch the widget: the gap is tiny at degree 3 and a chasm at degree 12, while train error only ever improves — train error is a liar with a consistent direction.
Memorize
  • bias–variance decomposition — noise + bias² + variance; holds exactly for squared error.
  • underfitting / overfitting — high bias / high variance; diagnosed by train-vs-validation gap.
  • capacity — richness of the hypothesis class (degree, width, depth).
  • double descent — test error can fall again past interpolation in over-parameterized nets.
  • early stopping — halting training as implicit regularization; cheap variance control.
Related: cross-validation, learning curves, effective capacity vs parameter count.
Quiz: diagnose from curves

Q: Train error 2%, val error 15%. Bias or variance? Two fixes. — Variance (big gap). More data, augmentation, stronger regularization, or smaller model.

Q: Train error 20%, val error 21%. Fixes? — Bias (both high, tiny gap). Bigger model, richer features, train longer, reduce regularization. More data will not help.

5. Regularization: L1 vs L2, and the AdamW subtlety

$$\mathcal{L}_{L2} = \mathcal{L}_{data} + \tfrac{\lambda}{2}\|w\|_2^2 \;\Rightarrow\; \nabla = \nabla\mathcal{L}_{data} + \lambda w \qquad\quad \mathcal{L}_{L1} = \mathcal{L}_{data} + \lambda\|w\|_1 \;\Rightarrow\; \text{subgradient } \lambda\,\text{sign}(w)$$

L2 adds a force proportional to the weight (big weights pulled hardest — "weight decay"); L1 adds a constant-magnitude force toward zero, which actually reaches zero → feature selection. Bayesian reading: L2 = Gaussian prior on weights, L1 = Laplace prior.

The AdamW subtlety (worth one sentence in any interview): with SGD, adding \(\frac{\lambda}{2}\|w\|^2\) to the loss and decaying weights directly are the same update. With Adam they are not: the L2 gradient term \(\lambda w\) gets divided by Adam's per-parameter \(\sqrt{\hat v}\), so frequently-updated weights are barely regularized. AdamW decouples the decay — applies \(w \leftarrow w - \eta\lambda w\) outside the adaptive rescaling — restoring uniform decay. That decoupling is the whole difference between Adam+L2 and AdamW.

Intuition. Ask "where does the shrinking force stop?" L2's force fades as the weight shrinks (proportional), so weights asymptote near zero but never land. L1's force stays constant, so small weights get shoved exactly to zero and pinned there by the corner of the diamond.
Memorize
  • L2 / weight decay / ridge — proportional shrinkage; Gaussian prior; keeps all features.
  • L1 / lasso — constant shrinkage; Laplace prior; exact sparsity.
  • AdamW — decoupled weight decay applied outside the adaptive-gradient rescaling; not equivalent to Adam + L2.
  • elastic net — L1 + L2 mixture; sparsity plus stability under correlated features.
  • implicit regularization — SGD noise, early stopping, augmentation, dropout regularize without a penalty term.
Related: MAP estimation, dropout, data augmentation as regularization.
Quiz: which penalty, and why

Q: 10,000 candidate features, you suspect ~50 matter. Which penalty? — L1 (or elastic net if features correlate): you want exact zeros, i.e. selection.

Q: Why did switching Adam → AdamW at the same λ change your results? — Adam+L2 scales the decay by the inverse adaptive step so hot parameters escape regularization; AdamW applies it uniformly. Same λ, different effective regularization.

6. Interactive: confusion matrix → metrics, and the imbalance trap

$$\text{precision} = \frac{TP}{TP+FP} \qquad \text{recall (TPR)} = \frac{TP}{TP+FN} \qquad F_1 = \frac{2PR}{P+R} \qquad \text{accuracy} = \frac{TP+TN}{\text{all}}$$

Precision conditions on your predictions ("when I raise an alarm, how often am I right?"); recall conditions on reality ("of the real events, how many did I catch?"). Only precision has FP in its denominator — so only precision feels the size of the negative pool. That asymmetry is the entire imbalance story: hold TPR and FPR fixed, multiply negatives by 100, and FP grows 100× while TP doesn't. Precision \(= \pi\,TPR / (\pi\,TPR + (1-\pi)FPR)\) collapses with prevalence \(\pi\); recall never moves.

AV framing: pedestrians in the far field are a 1:many-thousand problem per frame. A detector with a "great" 0.1% per-proposal FPR still buries you in false positives because proposals are almost all negative. You tune per-class thresholds against precision/recall at deployment prevalence, never against accuracy.

Intuition. Accuracy is a weighted vote where the majority class holds almost all the votes. At 1:100, the constant classifier "always negative" scores 99% — accuracy answers a question nobody asked. Precision and recall each condition away the imbalance in one direction; F1 forces you to be honest in both.
Memorize
  • precision — TP/(TP+FP); conditions on predictions; prevalence-sensitive.
  • recall / sensitivity / TPR — TP/(TP+FN); conditions on actual positives; prevalence-free.
  • F1 — harmonic mean of P and R; harmonic → the weaker one dominates.
  • prevalence π — positive fraction; the hidden variable behind every "accuracy is high" claim.
  • FPR / specificity — FP/(FP+TN) and its complement; the per-negative error rate.
Related: class weighting, focal loss, resampling, threshold tuning.
Quiz: the imbalance twist

Q: After the ×100 button, which metrics moved and which didn't? Why? — Recall and FPR are frozen (per-class rates). Precision and F1 collapsed (FP denominator grew 100×). Accuracy rose toward the TNR because negatives now dominate the average.

Q: Your rare-event classifier reports 99.2% accuracy. What do you ask first? — The prevalence, then precision/recall at the operating threshold.

7. ROC vs PR: the same classifier under two prevalences

ROC plots TPR vs FPR — both are within-class rates, so class mix never enters and the curve (and AUC) is prevalence-invariant. That invariance is a feature for comparing scoring functions and a bug for judging deployments: at 1:100, an FPR that looks tiny on the ROC x-axis is an avalanche of absolute false positives.

PR swaps the x-axis contaminant for precision, which mixes classes through its FP denominator: \(P = \pi\,TPR/(\pi\,TPR + (1-\pi)FPR)\). Same curve-generating scores, but at \(\pi = 0.01\) each unit of FPR costs 99× more precision. The PR baseline also shifts: a random classifier gets precision \(= \pi\), not 0.5 — so "PR-AUC 0.30" can be excellent at \(\pi=0.01\) and terrible at \(\pi=0.5\).

Rule: ROC/AUC to compare rankers or when both classes matter symmetrically; PR when positives are rare and FP cost is the pain (rare-object detection, safety triggers, alert pipelines).

Intuition. ROC asks "how well do you separate the two piles?" — a property of the scores. PR asks "how usable are your alarms?" — a property of the scores and the world. When the world is 99% negatives, only PR tells you what the on-call experience will be.
Memorize
  • ROC / AUC — TPR vs FPR; AUC = P(random positive scores above random negative); prevalence-invariant.
  • PR curve / AP — precision vs recall; baseline = prevalence; the imbalance-honest view.
  • operating point — one threshold = one point on either curve; deployment picks it by cost.
  • mAP — detection's mean AP over classes (and IoU thresholds in COCO) — PR is the backbone of every detection benchmark.
Related: detection-error tradeoff (DET) curves, cost curves, Youden's J.
Quiz: which curve lies?

Q: A colleague shows ROC-AUC 0.95 for a rare-defect detector and calls it deployable. What's the trap? — At low prevalence, high AUC coexists with unusable precision. Ask for the PR curve or precision at the required recall.

Q: Why is the ROC curve literally identical at both ratios in the figure? — TPR and FPR are each computed inside one class; changing how many of each class exist rescales counts, not rates.

8. Calibration: does 0.8 mean 80%?

A model is calibrated if, among all predictions made with confidence \(p\), a fraction \(p\) are correct. Accuracy and calibration are orthogonal: modern nets got more accurate and less calibrated (Guo et al. 2017) — CE training plus overfitting pushes confidences toward 1.

Temperature scaling is the embarrassingly effective fix: learn a single scalar \(T\) on a held-out set and predict with

$$p_i = \text{softmax}(z_i / T), \qquad T \text{ chosen to minimize validation NLL}$$

Because dividing all logits by the same \(T\) is monotone, argmax — and therefore accuracy, ROC, and every ranking metric — is exactly preserved; only the confidence values move. \(T > 1\) softens an overconfident model. One parameter, fit in seconds, and it's the standard first move before anything fancier (Platt scaling, isotonic regression, ensembles).

Why you care in an AV stack: downstream consumers — fusion, tracking, planning — treat the confidence as a probability when weighting evidence. An overconfident 0.99 on a phantom detection propagates as near-certainty into the planner. Calibration is a system-safety property, not a leaderboard nicety.

Intuition. Temperature scaling can't fix a bad ranker — it only relabels the confidence axis. If the reliability bars are non-monotone (some 0.6-bin outperforming the 0.8-bin), one global temperature can't repair that; you need isotonic regression or a better model.
Memorize
  • calibration — confidence matches empirical accuracy, per confidence level.
  • reliability diagram — binned confidence vs accuracy; diagonal = calibrated.
  • ECE — expected calibration error: bin-weighted average |accuracy − confidence|.
  • temperature scaling — one scalar on logits, fit on held-out NLL; preserves argmax, moves confidence.
  • overconfidence — the default failure of CE-trained deep nets.
Related: Platt scaling, isotonic regression, label smoothing (helps calibration a little), distillation temperature (§ inference page).
Quiz: what temperature scaling can and can't do

Q: Does temperature scaling change top-1 accuracy? mAP? ECE? — No, no, yes. Monotone transform → rankings untouched; only probability values (hence ECE, NLL, Brier) change.

Q: T fitted on validation comes out at 2.4. What does that say about the model? — Strongly overconfident: logits need substantial softening before confidences match reality.

9. Classical vs learned: when logistic regression and GBTs still win

The system-design round wants judgment, not deep-learning maximalism. The honest decision table:

SituationReach forWhy
Tabular features, ≤ ~100k rowsGradient-boosted trees (XGBoost/LightGBM)Still the strongest prior for heterogeneous tabular data; no representation to learn; handles missing values and mixed scales natively.
Need coefficients you can defend (safety case, regulator, ablation)Logistic regressionMonotone, auditable, convex (one global optimum), well-calibrated out of the box.
Milliseconds-and-microwatts budget (MCU-class edge, per-track gating)LR or a tiny treeA dot product beats a forward pass; trivial to verify and quantize.
Tiny labeled set, strong hand-crafted features existClassical + featuresDeep nets spend their sample budget learning features you already have.
Raw perceptual input: images, point clouds, audio, languageDeep nets, no contestFeature learning is the whole game; hand-crafted descriptors lost this fight in 2012.
Baseline / sanity harness for any of the aboveLR first, alwaysIf the deep model can't beat LR on your features, the pipeline — not the model — is the problem.

In an AV org both live side by side: deep nets own the sensor-to-semantics layers, while classical models still show up in trigger/gating logic, log mining, diagnostics classifiers, and anywhere a safety argument needs a model a human can read. Saying "I'd baseline with logistic regression before spending GPU-weeks" is a senior answer.

Intuition. Deep learning wins where the features must be learned; classical wins where the features already exist. Ask "what's the representation gap?" — if it's zero (tabular), the deep net has no edge and worse variance.
Memorize
  • GBTs — sequential trees fit to residual gradients; tabular king; watch for extrapolation failure outside the training hull.
  • convexity of LR — logistic loss is convex in w → one global optimum, deterministic training.
  • inductive bias — what each family assumes: trees = axis-aligned splits, convnets = locality + translation equivariance, transformers = learned pairwise relations.
  • baseline discipline — always price the simple model first; it's your denominator for "was the deep net worth it?"
Related: feature engineering, model cards, distillation of a big model into an auditable small one.
Quiz: pick the tool

Q: Classify which logged disengagements need human review, from 40 structured telemetry features, 30k labeled rows. — GBT (or LR baseline first). Tabular, small-ish, no representation gap; a deep net adds variance and opacity for nothing.

Q: When would you replace that GBT with a net? — When raw signals (camera clips, trajectories) enter the input and hand features start losing information — i.e., when a representation gap appears.
